# scripts/phi-allow-list.txt
#
# PHI-scan allow-list: the positive declaration that a fixture's identifiers
# are synthetic. `scripts/phi-scan.ts` reads this file; any realistic-PHI-shaped
# token NOT covered here is a hit. Byte-strict wire formats cannot carry an
# inline `# synthetic: true` header (the header segment must be the first bytes),
# so this allow-list is the synthetic-fixture declaration mechanism, the same
# approach every sibling `@cosyte/*` parser uses.
#
# Format: `<TAG> <value>` per line. `#` comments and blank lines are ignored.
#   NAME <token>          synthetic person-name word, matched case-insensitively
#   DOB <value>           synthetic date of birth (normalize as your detector does)
#   ID <value>            synthetic id matching an SSN / MRN / member-id shape
#   EMAILDOMAIN <domain>  reserved / test email domain that is allowed to appear
#   EMAIL <address>       one exact address, allowed wherever it appears
#
# WHICH TAGS THE SCANNER ACTUALLY CONSUMES. NAME feeds every structured name
# detector (HL7 PID-5, FHIR HumanName, C-CDA recordTarget, X12 NM1/PER, NCPDP
# SCRIPT + Telecom, ASTM P-6). EMAILDOMAIN and EMAIL feed the email floor. DOB and
# ID are loaded but consumed by nothing: no arm value-gates a DOB (a seeded
# synthetic DOB is indistinguishable from a real one, and there is no reserved DOB
# range), and the id arms check a SHAPE, SSA never-issued range, synthetic
# assigning authority, a failing NPI Luhn or DEA checksum, rather than a declared
# literal, because a generator mints ids per seed and a literal list would never
# keep up. Both tags are kept so a future rule has a declared source to read.
#
# To add a new synthetic fixture: reuse the tokens below, or append new ones here
# and commit. Adding a token is a reviewed, intentional act, never silent.

# --- Hand-written test tokens, NOT part of the generator's fake-name pool ---
#
# The two below are NOT in `src/safe/names-pool.ts` and must never be added to it.
# They are hand-written literals inside `test/deid/loop.test.ts`, which asserts what
# `recordTargetSentinels` DROPS, and they became visible the day the C-CDA arm stopped
# gating on the `.xml` file extension and started reading documents written inline in
# TypeScript. They were always in the repo; nothing could see them.
#
# Each is here rather than edited out of the fixture because the fixture needs exactly
# these shapes to prove its point, and rewriting a de-identifier test to quiet a PHI
# scanner would couple two gates and change what the test proves:
#   AL        a 2-character given name, present to prove the sentinel extractor drops
#             non-distinctive tokens. Any replacement must also be 2 characters, so no
#             pool name can stand in.
#   PROVIDER  a role word in an <author> name, present to prove author names are out of
#             the recordTarget sentinel scope.
#
# WHAT THIS COSTS, stated so a reviewer prices it rather than skims it: a NAME entry is
# global, so a `<given>Al</given>` or a PID-5 `Provider` now passes ANYWHERE in the repo.
# `Provider` is a role word no person is named, so that is close to free. `Al` is a real
# nickname, and declaring it is a genuine if small weakening: accepted because a
# 2-character token carries almost no identifying information, which is the same judgment
# the de-identifier under test already encodes by dropping it.
NAME AL
NAME PROVIDER
