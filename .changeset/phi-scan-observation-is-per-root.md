The PHI scanner can no longer report a clean sweep over a whole scan root it never opened.

`pnpm phi-scan` walks three roots: `src/`, `test/` and `scripts/`. It has always refused to print
`OK` over a scan that read nothing at all, on the grounds that an empty target set is indistinguishable
from a clean corpus. That rule was **global**, so it was satisfied by any one surviving file anywhere,
and one `src/` module was enough to vouch for all three roots.

Measured before the change, twice, on this package's own checkout:

```
# test/ moved aside
[phi-scan] OK - no hits (76 file(s) scanned)   exit 0

# test replaced by a dangling symlink
[phi-scan] OK - no hits (76 file(s) scanned)   exit 0
```

Both are a pass over a tree in which all 98 files of the test corpus went unread. Nothing else in the
scanner notices either state: the walk returns early on a root it cannot resolve, so absent, dangling
and empty are the same thing to it, and the refusal for an entry that is not a regular file never sees
a root, because it only classifies entries found _inside_ one. The count on the summary line was the
only signal there was, and 76 reads like a real number.

The rule is now **per-root**. An all-mode sweep refuses unless every declared root yielded at least one
file that was actually read, and the refusal names the roots that yielded nothing:

```
[phi-scan] refusing: the all-mode sweep observed no files under 1 of its 3 scan roots (test) ...
```

Reading nothing at all is now the all-roots case of that same rule rather than a separate one, so the
existing wording carries. Three behaviours are deliberately unchanged, and are pinned by tests so they
cannot drift: `--staged` and named-path invocations make no per-root promise, because a commit that
touches no file under `test/` is the ordinary case and a named path is bounded by the caller; and hits
found under the roots that did yield are still printed before the refusal, so an incomplete sweep never
swallows a real finding. The exit code is 2 rather than 1 in that case, because an incomplete sweep is
not a verdict whatever it turned up on the way.

**Its granularity is the declared root and nothing finer**, which is worth stating because the natural
way to describe this fix overstates it. An absent directory _inside_ a root is still unobserved under a
plausible denominator: `mv test/fixtures ..` still returns `OK - no hits (128 file(s) scanned)` and
exit 0 with 46 files unread. That is the same shape one level down, it is unchanged by this release, and
closing it needs a per-root floor derived from what the repository tracks, which is a separate decision.
The scanner's own limits list now records it alongside three more, each with the reading that produced
it.

This is a developer-facing gate rather than package API: no exported surface, generated byte, warning
code or type changes. It matters more in this package than in the parsers it consumes, though, because
this one exists to emit PHI-shaped bytes. A scan that silently observes nothing here is the emptiest
green there is.

Provenance: `PHI-SCAN-OBSERVED-NOTHING-IS-GLOBAL`. Found independently by two sibling repositories'
review passes, which is what made it an item rather than a note.
