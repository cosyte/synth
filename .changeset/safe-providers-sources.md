A generator whose parser is not installed now throws a `SynthError` with the new code `SYNTH_PEER_NOT_INSTALLED`, the same from the ES module build and the CommonJS build. Its message names the package and the command that installs it ("@cosyte/hl7 is not installed, and this generator builds through it. Install it beside @cosyte/synth: npm install @cosyte/hl7"), `err.peer` is the package, and `err.cause` is the error Node.js raised. Before, the CommonJS build threw `require`'s "Cannot find module '@cosyte/hl7'" (`MODULE_NOT_FOUND`), and the ES module build threw the same until the change below, which would have made it throw the resolver's "Cannot find package '@cosyte/hl7' imported from ..." (`ERR_MODULE_NOT_FOUND`). A caller that matched either message, or either Node.js code, checks `err.code === "SYNTH_PEER_NOT_INSTALLED"` instead, or reads `err.cause.code`. A missing dependency of an installed parser is not reported as the parser missing: that error is thrown as Node.js raised it. `SynthError` takes an optional second argument, `{ cause, peer }`, and the package root exports `SYNTH_PEER_MESSAGES` (one fixed message for each parser package) and the types `SynthPeer` and `SynthErrorOptions`.

A generator falls back to loading a parser by name only where `import.meta.resolve` throws the error Deno's test runner throws (`TypeError: Invalid arguments`), or answers with a URL that is not a `file:` URL. Before, any error from resolving fell back, so on Node.js a resolve that failed for another reason could load the CommonJS copy of a parser, whose classes `instanceof` does not recognize. Now such an error is thrown, and so is a `file:` URL that names no file path, which also used to fall back. The Deno case matches on that error's message, and no CI job runs under Deno yet, so it is tested only against a stand-in that throws the same error.

The synthetic-safety providers are now tested against the published ranges they cite, and three functions in that module read more simply with the same results. `isSyntheticPhone` checks that the number's digits end in `55501NN` with one pattern where it used two, and gives the same answer for every input. `luhnMod10` tests a doubled digit for 10 or more before subtracting 9, where it tested for more than 9. `ssn(rng, block?)` declares its second parameter optional instead of giving it a default; leaving it out still draws the never-issued space, and its type is unchanged. Generated output is unchanged.
